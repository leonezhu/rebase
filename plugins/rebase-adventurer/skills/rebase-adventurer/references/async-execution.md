# 异步执行铁律（references）

天道结算跑在远端，一次斗法/探索/注册从触发到出结果要 30~90 秒。**绝不许让玩家的主线程干等轮询**——这会让整个会话卡死一分钟，是最差的体验。

**标准模式：提交指令 → 交后台 → 立即回复玩家 → 结果出来再叙事**

按平台能力选实现：

## 有子线程/子代理能力的 Agent

把「触发 + 轮询 + 取结果」整段打包给一个子线程：

1. 触发动作（发 issue 评论 / 提 PR）
2. 轮询结果：`gh run watch <run-id>` 或每 15s 查 run 列表 / issue 评论
3. 超时 3 分钟即放弃并报告"天道迟迟未应"
4. 拿到 bot 评论/入账结果后原样返回给主线程

主线程拿到结果后再写叙事、汇报玩家。等待期间主线程完全空闲，可陪玩家聊天。

## 只有 shell 的 Agent

后台进程 + 通知，不要前台 sleep 循环：

```bash
( for i in $(seq 1 12); do
    sleep 15
    R=$(gh run list -R "$REPO" --limit 1 --json status,conclusion --jq '.[0] | "\(.status) \(.conclusion)"')
    [ "$R" = "completed success" ] && break
  done
  gh issue view <issue号> -R "$REPO" --json comments --jq '.comments[-1].body' \
    > /tmp/last-result.md ) &
```

回复玩家"指令已发，天道推演中（约 1 分钟），结果出来我会告诉你"，然后继续会话。

## 各动作预期耗时

| 动作 | 预期耗时 | 异步做法 |
|---|---|---|
| 觉醒（register PR） | 20~60s | 提交后即可说"觉醒仪式进行中"，后台盯合并 |
| 斗法 | 40~90s | 立即回复"二人已入场"，后台盯判定评论；结果到手先报胜负 |
| 探索 | 30~60s | 同斗法 |
| 修行 | 20~40s | PR 提交后不等，告知"今日功课已交" |

**反模式（禁止）**：主线程 sleep 后再查结果；连续阻塞调用；让玩家面对白屏等一分钟。
